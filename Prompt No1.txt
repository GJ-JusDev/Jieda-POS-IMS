
 # Build an Offline Desktop Inventory Management System

 You are a senior software architect and C#/.NET desktop developer. Build a professional, reliable, maintainable **offline Inventory Management System for Windows desktop**.

 The system will be used for everyday business operations, so prioritize **data integrity, reliability, usability, maintainability, security, backup/recovery, and clean architecture** over unnecessary complexity.

 ## 1\. Technology Stack

 Use the following technologies:

 - **Language:** C#
- **Framework:** Modern .NET (prefer the current LTS version available in the development environment)
- **Desktop UI:** WPF
- **Architecture:** Clean Architecture / layered architecture
- **ORM:** Entity Framework Core
- **Database:** SQLite
- **Database access:** EF Core with SQLite provider
- **Dependency Injection:** Microsoft.Extensions.DependencyInjection
- **Logging:** Microsoft.Extensions.Logging
- **Testing:** xUnit
- **Source control:** Git

 Do NOT use a web application, Electron, PHP, JavaScript-based desktop framework, or cloud database for the core application.

 The application must work **without an internet connection**.

 # 10\. Stock Transactions

 This is the most important inventory table.

 Create:

```
StockTransactions
-----------------

ProductId
TransactionType
Quantity
UnitCost
ReferenceType
ReferenceId
TransactionDate
CreatedBy
Notes
CreatedAt
```

 Transaction types should include:

 - Purchase
- Sale
- SaleReturn
- PurchaseReturn
- AdjustmentIncrease
- AdjustmentDecrease
- OpeningBalance

 Use positive quantities for stock additions and negative quantities for stock reductions, or use a clearly defined consistent convention.

 The system must preserve the transaction history.

 Do NOT silently delete historical stock transactions.

 Current stock should be calculated from the stock movement history or maintained using a carefully controlled mechanism that remains consistent with the transaction ledger.

 # 19\. Backup and Restore

 This is a critical requirement.

 The application must support:

 - Manual backup
- Automatic backup
- Restore backup
- Backup location configuration
- Backup history
- Backup validation

 Example:

```
C:\ProgramData\InventoryManagement\
│
├── Data\
│   └── Inventory.db
│
├── Backups\
│   ├── Inventory_2026-09-11.db
│   ├── Inventory_2026-09-12.db
│   └── Inventory_2026-09-13.db
│
└── Logs\
    └── application.log
```

 Create automatic backups based on a configurable schedule.

 Default:

 - Backup once per day.
- Keep the most recent 30 backups.

 Before restoring:

 - Require confirmation.
- Create a backup of the current database.
- Validate the selected backup.
- Clearly warn the user that restore will replace current data.

 Do not delete the current database before a valid backup has been created.

 # 21\. Data Integrity

 This is extremely important.

 Use database transactions for operations such as:

```
Complete Purchase
    ↓
Save Purchase
    ↓
Save Purchase Items
    ↓
Create Stock Transactions
    ↓
Commit
```

 And:

```
Complete Sale
    ↓
Validate Stock
    ↓
Save Sale
    ↓
Save Sale Items
    ↓
Create Stock Transactions
    ↓
Commit
```

 If any part fails, roll back the complete operation.

 Never leave a sale saved without its corresponding stock movement.

 Never leave a purchase saved as completed without its corresponding stock movement.

 # 29\. Important Design Rules

 Follow these rules throughout development:

 1. Do not put business logic directly into WPF code-behind.
2. Use MVVM.
3. Keep database access in Infrastructure.
4. Keep business rules in Application/Domain.
5. Use dependency injection.
6. Use async database operations where appropriate.
7. Use transactions for multi-step inventory operations.
8. Never silently alter historical stock transactions.
9. Never store plaintext passwords.
10. Never depend on internet connectivity for normal operation.
11. Never permanently delete transactional records unless there is a compelling reason.
12. Prefer deactivation/archiving for products, suppliers, and customers with historical transactions.
13. Validate user input.
14. Log unexpected errors.
15. Make backup and restore safe and explicit.
16. Keep the code readable and maintainable.
17. Avoid unnecessary third-party dependencies.
18. Do not hard-code configuration values.
19. Use configuration/settings for database and backup locations.
20. Do not sacrifice data integrity for convenience.
